# Loading fidelity and bounded cleanup — 2026-10-04

A subsequent bounded pass removes **26 source lines**, bringing current totals to **2,500 physical / 2,497 nonblank** across the same 29 files. It combines the duplicated feed start/refresh error boundary, replaces four pass-through state methods with type-only declarations, uses direct Marionette method-name bindings, reuses `Status`, and removes never-displayed tab defaults. All lifecycle guards and existing tests remain intact. The [current benchmark comparison](benchmark-comparison.md) and [trim snapshot](metrics/marionette-trim-run/build.json) identify the follow-up results; the loading evidence below remains the earlier snapshot.

## Contracts and ownership

The [neutral templates](https://github.com/realworld-apps/realworld/blob/ebbcdeb8d55b42a3a613c787560498b8ef10003f/docs/src/content/docs/specifications/frontend/templates.md) establish feed markup, and [the unchanged theme](../public/styles.css) gives `.article-preview` a 1 px top border and 1.5 rem vertical padding. The static template does not show every loading state. Both [Vue ArticleList](https://github.com/realworld-apps/vue-realworld-example-app/blob/f7e48c8178602ce25d43293bc6f8ca51d84ae222/src/components/ArticleList.vue) and [Angular ArticleList](https://github.com/realworld-apps/angular-realworld-example-app/blob/dd99ed2cf39c805d719f943c5d7061a5683d98a8/src/app/features/article/components/article-list.component.ts) explicitly use `<div class="article-preview">Loading articles...</div>` and suppress rows/pagination during loading. Their failure policies differ, so this implementation retains its existing explicit errors and Retry behavior. No Angular branding, signup, or footer choices were copied.

Installed Marionette and all four companion packages remain **5.0.0-rc.2**, documentation revision `f4243b8334cafe0bd1b06eba85d87e2310cb3618`. The packaged [retained-restart guide](../node_modules/marionette/docs/guides/retained-restart.md) assigns readiness and cancellation to Applications. The [View rendering contract](../node_modules/marionette/docs/api/view.md#rendering-and-status) says rerendering a layout resets its Regions and destroys children.

Accordingly, [FeedApplication](../src/features/feed/application.ts) still owns requests, status, writes, and collection updates. [FeedLayout](../src/features/feed/views.ts) borrows the status Model and changes only `hidden` on its existing result/pagination containers. It does not rerender or reconstruct those Regions for a pending-state change. This preserves in-flight write ownership and prevents invisible previous-query controls from remaining keyboard/accessibility targets. The Model binding is released with the View. No manual DOM insertion or new presentation abstraction was added.

Another shared action layer would hide those differences.                                                                                                                                                                                                                                                        |

The follow-up replaces runtime overrides with type-only `declare getState` signatures, preserving that typing and the inherited implementation. No extra typed base class or assertion helper was introduced.                                                                                                                                                                                                                     |

Its revision guard also preserves an existing direct-owner-method test that starts a favorite during a held read; hiding rows now prevents that interleaving through ordinary visible controls, but removing the guard would narrow that tested owner contract. Session authority protects credential changes; editor draft snapshots protect newer typing. Same-feature restart guards preserve the documented, tested Region/draft lifecycle, even though the UI does not add separate refresh controls for those features. No dead state or unused owner was demonstrated. |

## 2026-10-04 — implementation decisions

- [ConduitApplication](../src/app/application.ts) owns the persistent shell, browser navigation, session, and registered page Applications. [Home](../src/features/home/application.ts) and [Profile](../src/features/profile/application.ts) compose [Feed](../src/features/feed/application.ts); [Article](../src/features/article/application.ts) composes [Comments](../src/features/comments/application.ts). Applications own readiness, requests, and teardown; Regions and CollectionViews own presentation lifetimes. See [architecture](architecture.md).
- Organized each feature around `application.ts` and `view.ts` or `views.ts`, keeping related small Views together. [Auth](../src/features/auth/view.ts), [Editor](../src/features/editor/view.ts), and [Settings](../src/features/settings/view.ts) have named Views. [FormApplication](../src/shared/form-application.ts) shares save/status/cleanup policy; [field helpers](../src/shared/form-fields.ts) share markup.
- Used native Application subclasses for explicit instance-owned resources and typed lifecycle methods. Used `View.extend`/`CollectionView.extend` for declarative presentation and RC2's typed `initialize` option inference. Construction-time configuration lives on the prototype because native fields initialize after `super()`. Both syntaxes are supported; the [TypeScript guide](../node_modules/marionette/docs/guides/typescript.md) governs these boundaries.
- Configured the published Lit adapter and `@mnjs/data` providers in [setup](../src/setup.ts). Native Models have no fetch/save methods, so [transport](../src/shared/api.ts) handles HTTP and response validation explicitly. Attribute type aliases and ViewInstance narrowing follow the packaged declarations.
- [Session](../src/app/session.ts) owns credential lifetime and verification. Credential changes revoke previous requests; completion owners also check captured authority. Same-user verification retains the current page. Current-user 4xx responses clear credentials, while temporary server/network failure retains them, following the [user-fetch contract](https://github.com/realworld-apps/realworld/blob/ebbcdeb8d55b42a3a613c787560498b8ef10003f/specs/e2e/user-fetch-errors.spec.ts). Root navigation handles sign-out and rejects obsolete destination completions.
- `prepareStart` returns readiness data; `onStart` applies it. Feed queries use retained restart. Resource navigation uses stop/start. [Operation](../src/shared/operation.ts) owns active writes and cancellation on stop. Feed tracks active writes in one map, waits before reading, and repeats reads overlapped by writes. Unfavorites refresh membership/count after sibling writes settle; page repair replaces history so Back remains usable.
- Form status updates retain inputs. Editor compares submitted text/tags with the current draft; newer edits stay associated with the saved slug. Its `draft:saved` event lets the root own the URL update. Comment completion clears only unchanged submitted text. Namespaced comment intents keep comment deletion within its feature.
- Article action results update shared data and pending status together. Heading/body Views observe relevant fields; comment rows observe pending state. Framework bindings release borrowed-source listeners when Views are destroyed. Root window listeners are removed on stop; HMR destroys the root.
- Lit escapes ordinary content; [Markdown](../src/shared/presentation.ts) is sanitized with DOMPurify. Avatar URLs allow HTTP(S). The supplied theme's mobile column classes support full-width feed cards; initial loading preserves focus, while page navigation focuses the destination heading.

## 2026-10-04 — contract details

- Article-list responses omit `body`, per the [response contract](https://github.com/realworld-apps/realworld/blob/ebbcdeb8d55b42a3a613c787560498b8ef10003f/docs/src/content/docs/specifications/backend/api-response-format.md). Transport and fixtures distinguish ArticleSummary from full Article. Favorite responses apply the full returned article, consistent with the Vue reference.
- The prose update endpoint omits tags, but the [OpenAPI UpdateArticle schema](https://github.com/realworld-apps/realworld/blob/ebbcdeb8d55b42a3a613c787560498b8ef10003f/specs/api/openapi.yml) permits `tagList`, and [backend test 13](https://github.com/realworld-apps/realworld/blob/ebbcdeb8d55b42a3a613c787560498b8ef10003f/specs/api/bruno/articles/13-update-article-remove-all-tags-with-empty-array.bru) requires removal on update. The editor supports adding/removing tags and sends `tagList` in PUT.
- Test fixtures install interception automatically before navigation. The test API base is localhost, so a missing mock cannot write to the public API. Only disposable fixture credentials are used.

## Limitations

- The upstream RealWorld E2E suite and live backend interoperability were not run. Local fixtures verify frontend workflows, not backend authorization or server correctness.
- Upstream unavailable-state tests select literal `Connecting` text; this app displays unavailable/Retry copy. Local results do not establish compatibility with that selector.
- Client cancellation cannot undo accepted server writes. Unsaved drafts end with page teardown. Fonts/icons need network access; theme/avatar assets are local. A formal accessibility audit and deployment headers were not tested.
